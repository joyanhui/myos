# Pi 子进程委派

通过 `bash` 启动独立的 `pi -p` 子进程，将适合隔离的工作委派给它。子进程没有当前会话的历史，提示必须自包含；主进程负责判断输出、必要时核验，并向用户汇报。

## 触发边界

- 不得用于：目标文件已明确且少于 5 个的任务、普通代码读写、直接修改代码或运行常规构建/测试。此类工作在主会话完成。
- 可用于：陌生代码库的大范围调用链摸排、超过 10 个文件的全库盲搜、长日志分析、已完成变更的独立代码审查。
- 用户明确要求子进程、隔离上下文或独立审查时，可按用户指定范围委派。
- 修改文件仅在用户明确要求子进程执行修改时允许；否则子进程只做分析，不得写入。

## 执行规范

通过 bash 工具运行 `pi`，使用 `--no-session` 避免创建会话记录。不要把长提示直接拼入双引号；用单引号 heredoc 通过标准输入传递：

```bash
pi --no-session --tools read,grep,find,ls -p <<'EOF'
你是只读调研子进程，不具有主会话历史背景。
任务：[明确目标、范围、已知线索]
输出：只给结论、关键依据、文件路径和行号；不要输出思考过程或无关内容。
EOF
```

- 探索、日志分析和审查默认使用 `--tools read,grep,find,ls`，不得授予 `bash`、`edit` 或 `write`。
- 独立修改只在用户明确要求时使用 `pi --no-session -p`，提示中写清楚允许修改的范围和验收标准；不得以“研究”为由授予写权限。
- 用户要求指定模型时使用 `--model <provider/model>`；否则使用当前 pi 默认模型，不要擅自切换。
- 必要时通过 `git diff` 管道提供变更内容，例如：

```bash
git diff -- <path> | pi --no-session --tools read,grep,find,ls -p <<'EOF'
独立审查输入的 diff。需要时只读查看相关上下文。检查真实缺陷、安全问题和边界条件；仅报告可操作的问题及文件路径、行号，没有问题则明确说明。
EOF
```

审查时先确认 diff 范围，避免将无关或敏感内容传入子进程。不要将子进程输出视作已验证事实；主会话应按需核验关键结论。除非用户另有要求，最终只汇报有用结论，不转述推理过程。
