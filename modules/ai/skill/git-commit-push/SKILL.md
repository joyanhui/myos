# Git 提交并推送

将当前仓库工作区中的所有未提交改动按功能拆分为 commit，并推送到当前分支。默认纳入所有已跟踪和未跟踪文件，包括隐藏文件以及看起来包含凭据或敏感配置的文件；不得自行忽略、排除、暂缓提交或要求用户确认。只有用户明确指定提交范围时，才按指定范围处理。

- 先检查工作区状态、完整改动和近期提交记录。不得因改动看起来与当前任务无关、文件名以点开头、位于忽略规则覆盖的路径、包含凭据/敏感配置，或属于文件删除而擅自排除改动。
- 按功能分组提交；明显属于不同功能的改动应拆分为多个 commit。commit 总数不得超过 4 个；如果初步分组超过 4 组，应选择最相关的功能组进行适当合并，形成不超过 4 个逻辑清晰的 commit，并提交全部改动。不得因功能组超过 4 组而拒绝提交、遗漏改动或要求用户确认。新增、修改、重命名、复制和删除的文件都按正常改动提交；即使工作区只有一个或多个文件被删除，也必须提交删除，不得以没有其他改动为由拒绝。若需包含 Git 忽略规则覆盖的未跟踪文件，使用明确的文件路径暂存，不得因此跳过。
- 提交信息使用英文，格式为 `<type>(<scope>): <description>`；scope 可省略。type 使用常见前缀，如 `feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`chore`、`build`、`ci`、`revert`。
- 暂存所有应提交的文件；可以使用 `git add -A`。提交后确认结果。
- 全部完成后执行普通 `git push`。推送失败时停止并报告，不得强制推送。
- 不使用 `git commit --amend` 或 `--no-verify`。
- 无改动时报告工作区干净；无 remote 时说明未推送。
- 最后简要列出 commit 和推送结果。

## 安全边界

- 若改动包含冲突标记，停止并报告。
- 不得覆盖工作区更改或改写既有提交。
- 遇到提交钩子失败，报告失败原因；不得擅自绕过钩子。
