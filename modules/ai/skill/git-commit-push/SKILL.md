# Git 提交并推送

本技能只负责检查 Git 改动、生成 commit 信息、创建 commit 和推送。不要执行任何与提交无关的检查、构建、修复或审查工作。

## 执行流程

1. 检查当前分支和 Git 工作区状态，确认全部待提交改动。用户未指定范围时，纳入所有已跟踪和未跟踪改动，包括隐藏文件、删除文件、敏感配置、凭据变更及看似与当前任务无关的改动；不得自行排除、遗漏、要求确认或拒绝。
2. 查看必要的 diff，仅用于理解改动、按功能分组和生成准确的 commit 信息。不得据此修改文件、做代码审查或决定不提交。
3. 按功能组织 commit，最多 4 个。超过 4 组时适当合并功能组，确保全部改动纳入且总数不超过 4。
4. 暂存并提交全部改动。可使用 `git add -A`；需要纳入但被忽略的未跟踪文件，使用 `git add -f -- <path>`。提交信息使用英文，格式为 `<type>(<scope>): <description>`，scope 可省略。
5. 确认 commit 成功后，对当前分支执行普通 `git push`。没有 remote 时仍完成本地提交，并说明无法推送。push 失败时保留 commit，报告具体错误，不强推。
6. 简要报告创建的 commit 和 push 结果。

## 严格禁止的额外工作

不要运行 `cargo check`、`cargo test`、`cargo clippy`、TypeScript 检查、任何语言或框架的测试、类型检查、lint、格式检查、构建、部署、基准测试或其他验证命令。不要为了提交而修复代码、调整格式、清理文件、修改配置或处理凭据。不要启动与 Git 提交和推送无关的任务。

编译错误、测试失败、lint 问题、冲突标记文本、凭据或配置值的增删、隐藏文件、删除文件、改动量大，均不是拒绝提交的理由；不执行相应检查，直接按 Git 改动生成提交并推送。

## 操作限制

- 不使用 `git commit --amend`、`--no-verify`、强制推送或其他改写既有提交的操作。
- 不覆盖、恢复、清理或改写用户现有改动。
- 仅在 Git 命令实际失败时报告该命令的具体错误；仍继续完成其他可执行的 Git 操作。无改动时报告工作区干净。
