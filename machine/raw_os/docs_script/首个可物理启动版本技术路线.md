# 首个可物理启动版本技术路线

## 项目目标

把 NixOS 打包成一个自包含镜像文件 nixos.raw，放在任意宿主机的 NTFS 分区下，通过外部 GRUB2 以 loopback 方式直接启动（免 dd、免烧录 U 盘、不写入目标硬盘）。同时镜像本身也兼容 dd 到硬盘/直连磁盘启动。

## 整体架构

一条完整的启动链路，分三段：

- 宿主引导：宿主 ESP 上的 grubx64.efi（单文件，内嵌配置）负责找到宿主 NTFS 分区里的 nixos.raw，用 loopback 把它映射成虚拟磁盘。
- initrd 服务：镜像自带的 systemd initrd 服务 nixos-img-loop-for-root 把宿主 NTFS 分区挂载出来，读取 nixos.raw 并 losetup，让镜像内部的 root 分区变成可用的块设备。
- root 挂载：NixOS 通过 /dev/disk/by-partlabel/nixos-root 挂载镜像内部的 btrfs root 分区，进入系统。

技术栈：NixOS（flake + home-manager 体系）、nixpkgs 的 image/repart 模块（systemd-repart 生成 GPT 镜像）、systemd-boot + UKI（镜像内部引导）、GRUB2（外部引导，loopback 加载镜像文件）、ntfs3 内核驱动（挂载宿主 NTFS）、systemd 的 initrd 服务机制。

## 镜像构建

### 入口与模块

- flake.nix 定义 host `raw_os_core_img_creat`，模块指向 machine/raw_os/raw-os-core-img-creat.nix。
- raw-os-core-img-creat.nix 继承 minimal.nix 与 image/repart.nix，产出镜像 derivation。
- system.image.id = "nixos-img"；镜像文件名为 nixos.raw（image.repart.name = "nixos"）。

### 分区布局（systemd-repart）

- esp：vfat，64M，label=ESP。内容为 systemd-boot EFI 文件（/EFI/BOOT/BOOTX64.EFI）和 UKI（/EFI/Linux/nixos-img.efi）。systemd-boot 提供镜像内部 EFI 直启（dd 到盘时生效）。
- root：btrfs，固定 10G，label=nixos-root。storePaths 放入 toplevel 与 system.path；根目录内容来自 imageRootTree。

### 根目录骨架 imageRootTree

repart 的 root 分区内容默认只有 /nix/store，NixOS 启动还需要根目录骨架。imageRootTree 用 runCommand 生成：

- 顶层目录：/run /var /tmp /home /root /boot /dev /proc /sys /usr /bin /lib /lib64 /sbin /opt /srv /mnt /media /lost+found。
- /tmp、/var/tmp 设 1777。
- /usr/bin/env 链接到 coreutils env（systemd 要求 /usr 非空）。
- /etc 实体化为真实可写目录（cp -a toplevel/etc/. 到 /etc），否则 activation 无法写 passwd/shadow。
- /nix/var/nix/profiles/system 与 /run/current-system 链接到 toplevel。
- /init 与 /sbin/init 链接到 toplevel/init。

### 用户与登录

- 用户 nixos，isNormalUser + wheel 组，密码 nixos（用于登录与应急 shell）。
- getty autologinUser = nixos（开机自动登录进控制台）。
- environment.sessionVariables.PATH 显式给出 /run/current-system/sw/bin 等。

### 包集合

- 镜像内 systemPackages 用 mkForce 显式指定（minimal 继承的默认包全部裁掉），保留：coreutils、bash、git、fish、networkmanager、updateGrubx64LoopbackEfi、helix、usbutils、pciutils、parted、gptfdisk、btrfs-progs、dosfstools、fastfetch、wget、curl、yazi、unzip、p7zip、psmisc、htop、iftop、fd、tree、jq、bat、dos2unix、dnsutils、iproute2、tcpdump、tmux、openssl、ntfs3g、inetutils、exfat、sshfs-fuse、smartmontools、nvme-cli、efibootmgr、cryptsetup、qemu-utils、resize-raw-image、rsync。
- bash 与 coreutils 必须保留（root 骨架与登录 shell 依赖），updateGrubx64LoopbackEfi 为镜像内更新引导的脚本。

### 文件系统配置

- /：btrfs，compress=zstd，设备 /dev/disk/by-partlabel/nixos-root。
- /var、/tmp：tmpfs（root 保持只读部署，可写面放到内存）。
- /boot：指向 /dev/disk/by-partlabel/ESP，vfat。

## initrd 配置与 nixos-img-loop-for-root 服务

### 模块与驱动

- boot.initrd.kernelModules = [ "loop" "ntfs3" ]：强制加载 loop 与 ntfs3。
- boot.initrd.availableKernelModules：磁盘控制器驱动 + 文件系统驱动全列全：
  nvme、ahci、libahci、libata、sd_mod、virtio_pci、virtio_blk、usb-storage、xhci_pci、ehci_pci、ext4、xfs、btrfs、vfat、exfat。
  enableAllHardware 只影响 stage2，initrd 必须显式列出，否则物理机 NVMe 盘在 initrd 阶段不出现。
- boot.initrd.systemd.initrdBin = [ util-linux ]：把 blkid、mount、losetup 等带进 initrd。

### 服务定义

- wantedBy = initrd.target；before = initrd-root-device.target、sysroot.mount；after = systemd-udevd.service。
- path = util-linux + coreutils + kmod。
- Type = oneshot。

### 脚本逻辑

- dbg() 每步打印到 /dev/console（物理机屏幕可见）与 /dev/ttyS0（调试串口）。
- 等块设备枚举：最多 10 轮 × 1 秒轮询 /dev/vd*、sd*、nvme*、hd*、mmcblk*。
- 直启检测：任一分区 LABEL=nixos-root 已存在（dd 到盘/直连场景）→ 跳过直接 exit 0。
- 宿主扫描：单轮遍历所有块设备，blkid TYPE=ntfs 才处理；mkdir /host，timeout 4 秒 mount -t ntfs3；检查 /host/OS-img/nixos.raw 是否存在；不存在则 umount 继续下一个。
- 找不到宿主分区或文件 → exit 1（显性失败，屏幕已打印原因）。
- losetup：losetup -fP /host/OS-img/nixos.raw，失败 exit 1。
- udevadm trigger --subsystem-match=block + udevadm settle --timeout=10，让 loop 分区节点与 device unit 生成。
- 手动建立 /dev/disk/by-partlabel 链接：遍历 /dev/loop*p*，blkid 取 LABEL，ln -sf 建 ESP 与 nixos-root 链接（不依赖 udev 时序）。
- 找到镜像后通过 losetup 创建 loop 设备并建立分区链接；保留 `/host` 挂载，使 loop 设备继续引用宿主分区中的镜像文件。

### 关键设计要点

- 单轮扫描而不是多轮循环：物理机常有多个 NTFS 分区，旧版多轮 × 每分区 10 秒会超过 systemd 默认 90 秒超时被杀死导致 FAILED。
- 失败不吞错：mount/losetup 的 stderr 原文通过 dbg 打印到屏幕，任何失败一眼可见。
- 服务保持正常失败行为（exit 1），不做人为 exit 0 掩盖；失败时屏幕已留原因。

## 引导文件生成（machine/raw_os/docs_script/create-grubx64-efi.sh）

### 输入与产物

- 输入：toplevel 的 boot.json（kernel、initrd、init、kernelParams）。
- 产物：grubx64.efi（约 12M 单文件），grub-mkstandalone 生成，内嵌静态 grub.cfg，--compress=no。
- 选项：-o 输出路径；-s / --serial 追加 console=ttyS0,115200 console=tty0（KVM 调试用）。

### 内嵌 grub.cfg 流程

- insmod：ntfs、part_gpt、btrfs、search、search_fs_file、configfile、normal、linux、loopback、all_video。
- search --no-floppy --set=root --file /OS-img/nixos.raw：定位宿主分区。
- set vdisk=($root)/OS-img/nixos.raw；loopback loop0 $vdisk。
- linux (loop0,gpt2)$kernel init=$init $params（gpt2 即镜像内部 root 分区）。
- initrd (loop0,gpt2)$initrd。
- boot。

## 镜像内更新脚本（updateGrubx64LoopbackEfi）

镜像内 systemPackages 自带 update-grubx64-loopback-efi，nixos-rebuild 后运行可重生成引导文件：

- 读 /run/current-system/boot.json 取新 kernel/initrd/init/params。
- grub-mkstandalone 生成新 grubx64.efi。
- 遍历所有块设备，挂载 vfat 分区，找到含 EFI/BOOT/BOOTX64.EFI 或 grubx64.efi 的 ESP，把新文件写入 BOOTX64.EFI 与 grubx64.efi 并 sync。
- 输出更新了哪些 ESP 分区。

## 扩容 raw 镜像

`machine/raw_os/docs_script/resize-raw-image.sh` 是非交互式扩容脚本。它会先检查镜像是否已挂载或已关联 loop 设备；只允许未挂载、未使用的镜像继续操作。参数指定新的镜像大小，并通过参数决定是否立即挂载第二分区执行 `btrfs filesystem resize max`。镜像内已经安装同名命令，可在启动后的 raw OS 中扩容另一个未挂载的 raw 镜像。

```bash
machine/raw_os/docs_script/resize-raw-image.sh nixos.raw 20G --resize-btrfs
# 只扩展镜像文件和分区，不扩展 Btrfs
machine/raw_os/docs_script/resize-raw-image.sh nixos.raw 20G --skip-btrfs-resize
# 镜像内
sudo resize-raw-image /mnt/other/nixos.raw 20G --resize-btrfs
```

扩容前应确保没有其他程序同时写入目标镜像。`--resize-btrfs` 会在扩展分区后临时挂载并扩展 Btrfs；`--skip-btrfs-resize` 只扩展镜像文件和分区。

## VHD 转换

`machine/raw_os/docs_script/additional-foot-to-raw-and-renameVHD.sh` 将 raw 镜像转换为 fixed VHD，并在成功复制后删除原始 `.raw` 文件。它不会改变镜像内部的 GPT 和分区布局；需要保留 raw 文件时，先复制一份再执行脚本。

```bash
nix shell nixpkgs#qemu -c machine/raw_os/docs_script/additional-foot-to-raw-and-renameVHD.sh nixos.raw
```

## 部署方式

- nixos.raw：复制到宿主 NTFS 分区根目录的 OS-img/ 下（文件名与目录由 grub.cfg 和 initrd 服务共同约定）。
- grubx64.efi：复制到宿主 ESP 的 /EFI/Boot/grubx64.efi；如需无 NVRAM 机器的 UEFI fallback，再复制一份到 /EFI/Boot/BOOTX64.EFI。仓库中的样例文件与脚本位于 machine/raw_os/docs_script/。
- 构建命令：nix build .#nixosConfigurations.raw_os_core_img_creat.config.system.build.image。
- 重新生成引导：先构建 toplevel，再用该 toplevel 中的 boot.json 运行 `machine/raw_os/docs_script/create-grubx64-efi.sh <boot.json> -o grubx64.efi`。脚本需要 `jq` 和 `grub-mkstandalone`，可执行 `nix shell nixpkgs#jq nixpkgs#grub2_efi -c machine/raw_os/docs_script/create-grubx64-efi.sh <boot.json> -o grubx64.efi`。
