# raw OS 测试和验证方法

测试目录：`/tmp/raw-os-kvm-uki/`

## 构建镜像和 UKI

image 和 uki 必须来自同一次构建，两条 nix build 在同一条命令中执行：

```bash
set -euo pipefail
work=/tmp/raw-os-kvm-uki
rm -rf "$work"
mkdir -p "$work"

image_dir=$(nix build --no-link --print-out-paths \
  .#nixosConfigurations.raw_os_core_img_creat.config.system.build.image \
  --option substituters https://cache.nixos.org)
uki_dir=$(nix build --no-link --print-out-paths \
  .#nixosConfigurations.raw_os_core_img_creat.config.system.build.uki \
  --option substituters https://cache.nixos.org)

cp --reflink=auto "$image_dir/nixos.raw" "$work/nixos.raw"
machine/raw_os/docs_script/create-nixos-img-uki-efi.sh \
  "$uki_dir" -o "$work/nixos-img.efi"
```

检查产物：

```bash
qemu-img info "$work/nixos.raw"
file "$work/nixos-img.efi"
```

## 准备外部启动测试盘

外部盘由 1 GiB ESP 和 NTFS 分区组成。内部镜像 ESP 标签固定为 `nixos-esp`，外部 ESP 用 `ESP`，两者不冲突。

```bash
qemu-img create -f raw "$work/host.raw" 16G
nix shell nixpkgs#gptfdisk -c sgdisk --zap-all "$work/host.raw"
nix shell nixpkgs#gptfdisk -c sgdisk \
  -n 1:2048:+1G -t 1:EF00 -c 1:ESP \
  -n 2:0:0 -t 2:0700 -c 2:HOSTNTFS \
  "$work/host.raw"
qemu-img convert -f raw -O qcow2 "$work/host.raw" "$work/host.qcow2"
rm "$work/host.raw"
```

通过 NBD 格式化并写入分区：

```bash
sudo $(nix build --no-link --print-out-paths nixpkgs#kmod)/bin/modprobe nbd max_part=8
sudo qemu-nbd --format=qcow2 --connect=/dev/nbd0 "$work/host.qcow2"
sudo mkfs.vfat -F 32 -n ESP /dev/nbd0p1
sudo mkfs.ntfs -F -L HOSTNTFS /dev/nbd0p2
sudo mkdir -p "$work/mnt/esp" "$work/mnt/ntfs"
sudo mount /dev/nbd0p1 "$work/mnt/esp"
sudo mount -t ntfs-3g /dev/nbd0p2 "$work/mnt/ntfs"
sudo mkdir -p "$work/mnt/esp/EFI/NixOS" "$work/mnt/ntfs/OS-img"
sudo cp "$work/nixos-img.efi" \
  "$work/mnt/esp/EFI/NixOS/nixos-img.efi"
sudo cp "$work/nixos.raw" "$work/mnt/ntfs/OS-img/nixos.raw"
sudo sync
sudo umount "$work/mnt/esp" "$work/mnt/ntfs"
sudo qemu-nbd --disconnect /dev/nbd0
```

- ESP 必须是 1 GiB：`updateExternalEfi` 先在目标目录写临时文件再原子替换，ESP 过小会报 `No space left on device`。
- 不要给外部 ESP 改名，也不要用 `nixos-esp` 作为外部标签，否则 `/boot` 会挂载到错误分区。

目录结构：

```text
ESP/EFI/NixOS/nixos-img.efi
HOSTNTFS/OS-img/nixos.raw
```

## KVM 启动并注册外部启动项

使用 QEMU 固件和临时 NVRAM 文件启动宿主 qcow2：

```bash
cp --reflink=auto kvm-config/firmware/OVMF_VARS.fd \
  "$work/OVMF_VARS-test.fd"

timeout --signal=TERM --kill-after=10s 120s \
  qemu-system-x86_64 \
    -name raw-os-external-uki-test \
    -enable-kvm \
    -machine q35,accel=kvm \
    -cpu host \
    -smp 2 \
    -m 2G \
    -drive if=pflash,format=raw,readonly=on,\
file=$PWD/kvm-config/firmware/OVMF.fd \
    -drive if=pflash,format=raw,\
file=$PWD/tmp/raw-os-kvm-uki/OVMF_VARS-test.fd \
    -drive if=virtio,format=qcow2,\
file=$PWD/tmp/raw-os-kvm-uki/host.qcow2 \
    -display none \
    -chardev file,id=serial,\
path=$PWD/tmp/raw-os-kvm-uki/qemu-external-uki-serial.log \
    -serial chardev:serial \
    -monitor none
```

首次进入系统后注册外部启动项并固定下一次启动：

```bash
sudo efibootmgr -c -d /dev/vda -p 1 -L NixOS-External -l '\EFI\NixOS\nixos-img.efi'
sudo efibootmgr -n 0005   # 0005 换成上一条命令输出的 BootXXXX 编号
sudo reboot
```

第二次启动必须确认 `BootCurrent: 0005` 后再验收。若固件回退到内部启动项，脚本会正确报 `GPT partition UUID was not found`，此时先恢复外部 EFI 文件再启动。

## 验收 updateExternalEfi

串口没有可靠的登录 prompt，不要在 shell 交互里等待提示符。推荐两种方式。

方式一：一次性 systemd 服务（推荐）

在 `raw-os-runtime.nix` 临时加入 oneshot 服务，自动执行截断、更新、比较，把结果写串口：

```nix
systemd.services.updateExternalEfiAcceptance = {
  wantedBy = [ "multi-user.target" ];
  after = [ "local-fs.target" ];
  serviceConfig.Type = "oneshot";
  path = with pkgs; [ coreutils util-linux ];
  script = ''
    mountpoint=/mnt/external-esp
    mkdir -p "$mountpoint"
    mount -t vfat /dev/vda1 "$mountpoint"
    truncate -s 1 "$mountpoint/EFI/NixOS/nixos-img.efi"
    sync
    umount "$mountpoint"

    updateExternalEfi
    mount -t vfat /dev/vda1 "$mountpoint"
    cmp -s /boot/EFI/Linux/nixos-img.efi "$mountpoint/EFI/NixOS/nixos-img.efi"
    stat -c "UPDATED_SIZE=%s" "$mountpoint/EFI/NixOS/nixos-img.efi"
    umount "$mountpoint"
  '';
};
```

重建镜像和 UKI 后重做准备工作，启动一次即可看到 `updated: /EFI/NixOS/nixos-img.efi` 和 `UPDATED_SIZE=48934400`。验收后必须删除该服务并重新构建交付产物。

方式二：expect 固定标记

发送命令后只匹配固定结果，不匹配 shell prompt：

```tcl
spawn nc 127.0.0.1 45555
expect -re {automatic login}
send "sudo updateExternalEfi; echo UPDATE_RC=\$?\r"
expect -re {updated: /EFI/NixOS/nixos-img.efi}
expect "UPDATE_RC_0"
```

常见坑：

- 等待 `nixos@nixos:~$` 再发送命令，会被登录输出或回显抢跑，命令没执行。
- expect 匹配到输入回显而不是命令输出，会提前发送下一条命令。
- 用 `stty -echo` 后串口没有 prompt，expect 等不到提示符。
- 当前启动项不是外部项时脚本报 `GPT partition UUID was not found`，这是正确保护，不是失败。

## 离线验收

关机后比较三个文件，三份必须同哈希、同大小（`48934400` 字节）：

```bash
sudo qemu-nbd --format=qcow2 --connect=/dev/nbd0 "$work/host.qcow2"
sudo mount /dev/nbd0p1 "$work/mnt/esp"
sha256sum "$work/nixos-img.efi" "$work/mnt/esp/EFI/NixOS/nixos-img.efi"
cmp "$work/nixos-img.efi" "$work/mnt/esp/EFI/NixOS/nixos-img.efi"
sudo umount "$work/mnt/esp"
sudo qemu-nbd --disconnect /dev/nbd0

sudo qemu-nbd --format=raw --connect=/dev/nbd0 "$work/nixos.raw"
sudo mount /dev/nbd0p1 "$work/mnt/raw-esp"
sha256sum "$work/mnt/raw-esp/EFI/Linux/nixos-img.efi"
sudo umount "$work/mnt/raw-esp"
sudo qemu-nbd --disconnect /dev/nbd0
```

## 清理

```bash
sudo umount "$work/mnt/esp" "$work/mnt/ntfs" 2>/dev/null || true
sudo qemu-nbd --disconnect /dev/nbd0 2>/dev/null || true
sudo losetup -D 2>/dev/null || true
rm -rf "$work"
```

## 交付到 Windows

构建产物写入 Windows NTFS 分区（WSL 挂载为 `/mnt/n`）：

```bash
sudo cp "$work/nixos-img.efi" /mnt/n/OS-img/nixos-img.efi
sudo cp "$work/nixos.raw" /mnt/n/OS-img/nixos.raw
```

交付文件名固定为 `nixos.raw` 和 `nixos-img.efi`。
