# raw OS KVM 测试和验证方法

本流程用于验证以下三件事：

- raw 镜像可以从内部 `EFI/BOOT/BOOTX64.EFI` 启动。
- 内部启动时，`nixos-rebuild switch` 可以原子更新 `/boot/EFI/BOOT/BOOTX64.EFI`。
- 外部自定义 EFI 启动时，`updateExternalEfi` 可以更新当前 UEFI 启动项指向的 EFI 文件。

不要把下面的测试简化为“能进 shell”。每个阶段都必须等到规定的成功标记，前置阶段失败时停止，不得继续发送后续命令。

## 固定约定

```text
测试目录：/tmp/raw-os-kvm-uki
raw 镜像：nixos.raw
内部 EFI：EFI/BOOT/BOOTX64.EFI
外部 EFI：EFI/NixOS/nixos-img.efi
外部 NTFS：OS-img/nixos.raw
内部 ESP 标签：nixos-esp
外部 ESP 标签：ESP
```

约束：

- 内部和外部 EFI 是同一批构建生成的 UKI 副本，但路径不同、用途不同。
- 外部 EFI 不使用 `EFI/BOOT/BOOTX64.EFI`，路径由 UEFI 启动项决定。
- 外部 ESP 必须至少 1 GiB。`updateExternalEfi` 需要临时文件和原子替换空间。
- 外部 raw 文件必须使用 `cp --sparse=never` 写入 NTFS，避免稀疏文件或 NTFS 写回造成误判。
- 两种启动测试必须使用独立的 OVMF_VARS 文件，不能复用已有虚拟机的 NVRAM。
- QEMU 进程、NBD、挂载点没有清理干净时，不得开始下一轮测试。
- 串口超时不是成功也不是失败。只有固定成功标记出现，测试才算完成。

## 0. 测试前清理和临时串口配置

测试需要自动登录和串口控制台。只为测试临时加入以下配置：

```nix
boot.kernelParams = [ "console=ttyS0" ];
systemd.services."serial-getty@ttyS0".enable = true;
```

测试结束后必须删除这两项，并重新构建交付产物。不要把测试配置写入最终交付的 raw 镜像。

开始前执行：

```bash
set -euo pipefail

work=/tmp/raw-os-kvm-uki
sudo umount -l "$work"/mnt/esp "$work"/mnt/ntfs "$work"/mnt/raw-esp 2>/dev/null || true
sudo qemu-nbd --disconnect /dev/nbd0 2>/dev/null || true

if ps -eo args | grep -E '[q]emu-system|[q]emu-nbd|[m]ount.ntfs' >/dev/null; then
  echo 'error: previous KVM or NBD process is still running' >&2
  exit 1
fi

rm -rf "$work"
mkdir -p "$work"
```

## 1. 一次性构建同一批产物

image 和 UKI 必须在同一条 `nix build` 中构建。不要先构建 raw、之后再单独构建 UKI。

```bash
set -euo pipefail

mapfile -t outputs < <(
  nix build --no-link --print-out-paths \
    .#nixosConfigurations.raw_os_core_img_creat.config.system.build.image \
    .#nixosConfigurations.raw_os_core_img_creat.config.system.build.uki \
    --option substituters https://cache.nixos.org
)

image_dir=${outputs[0]}
uki_dir=${outputs[1]}
work=/tmp/raw-os-kvm-uki

cp --reflink=auto "$image_dir/nixos.raw" "$work/nixos.raw"
machine/raw_os/docs_script/create-nixos-img-uki-efi.sh \
  "$uki_dir" -o "$work/nixos-img.efi"

qemu-img info "$work/nixos.raw"
file "$work/nixos-img.efi"
stat -c '%n %s bytes' "$work/nixos.raw" "$work/nixos-img.efi"
```

构建门禁：

- `nixos.raw` 和 `nixos-img.efi` 都必须存在。
- `nixos-img.efi` 必须是 x86-64 EFI executable。
- 后续所有步骤只能使用 `$work` 中的这两个文件。

## 2. 创建唯一的外部测试盘

外部测试盘包含 1 GiB ESP 和 NTFS 分区。测试盘必须每轮重新创建，不能复用上次被截断或被 guest 写回过的盘。

```bash
set -euo pipefail

work=/tmp/raw-os-kvm-uki
qemu-img create -f raw "$work/host.raw" 16G

nix shell nixpkgs#gptfdisk -c sgdisk --zap-all "$work/host.raw"
nix shell nixpkgs#gptfdisk -c sgdisk \
  -n 1:2048:+1G -t 1:EF00 -c 1:ESP \
  -n 2:0:0 -t 2:0700 -c 2:HOSTNTFS \
  "$work/host.raw"

qemu-img convert -f raw -O qcow2 "$work/host.raw" "$work/host.qcow2"
rm "$work/host.raw"

sudo nix shell nixpkgs#kmod -c modprobe nbd max_part=8
sudo qemu-nbd --format=qcow2 --connect=/dev/nbd0 "$work/host.qcow2"

cleanup_nbd() {
  sudo umount -l "$work/mnt/esp" "$work/mnt/ntfs" 2>/dev/null || true
  sudo qemu-nbd --disconnect /dev/nbd0 2>/dev/null || true
}
trap cleanup_nbd EXIT

for i in $(seq 1 20); do
  [ -b /dev/nbd0p1 ] && [ -b /dev/nbd0p2 ] && break
  sleep 1
done
[ -b /dev/nbd0p1 ] && [ -b /dev/nbd0p2 ]

sudo mkfs.vfat -F 32 -n ESP /dev/nbd0p1
sudo mkfs.ntfs -F -L HOSTNTFS /dev/nbd0p2
sudo mkdir -p "$work/mnt/esp" "$work/mnt/ntfs"
sudo mount /dev/nbd0p1 "$work/mnt/esp"
sudo mount -t ntfs-3g /dev/nbd0p2 "$work/mnt/ntfs"

sudo mkdir -p "$work/mnt/esp/EFI/NixOS" "$work/mnt/esp/EFI/BOOT" "$work/mnt/ntfs/OS-img"
sudo cp --sparse=never "$work/nixos-img.efi" \
  "$work/mnt/esp/EFI/NixOS/nixos-img.efi"
sudo cp --sparse=never "$work/nixos-img.efi" \
  "$work/mnt/esp/EFI/BOOT/BOOTX64.EFI"
sudo cp --sparse=never "$work/nixos.raw" \
  "$work/mnt/ntfs/OS-img/nixos.raw"
sudo sync

sudo sha256sum "$work/mnt/ntfs/OS-img/nixos.raw"
sudo cmp "$work/nixos.raw" "$work/mnt/ntfs/OS-img/nixos.raw"
sudo find "$work/mnt/esp/EFI" -maxdepth 3 -type f -printf '%P %s bytes\n'
sudo find "$work/mnt/ntfs/OS-img" -maxdepth 1 -type f -printf '%P %s bytes\n'

sudo umount "$work/mnt/esp" "$work/mnt/ntfs"
sudo qemu-nbd --disconnect /dev/nbd0
trap - EXIT
```

准备门禁：

```text
ESP/EFI/NixOS/nixos-img.efi
ESP/EFI/BOOT/BOOTX64.EFI    # 仅用于第一次注册外部启动项
HOSTNTFS/OS-img/nixos.raw
```

第一次注册外部启动项依赖外部 ESP 的临时 fallback。确认 `BootNext` 已设置并完成关机/重启后，离线删除该临时文件。最终外部验收必须确认 `BootCurrent` 指向 `EFI/NixOS/nixos-img.efi`，内部 fallback 文件只属于 `nixos.raw` 内部 ESP。

## 3. QEMU 固件和串口规则

每种场景使用独立的 OVMF_VARS：

```bash
cp --reflink=auto kvm-config/firmware/OVMF_VARS.fd \
  "$work/OVMF_VARS-internal.fd"
cp --reflink=auto kvm-config/firmware/OVMF_VARS.fd \
  "$work/OVMF_VARS-external.fd"
chmod 644 "$work"/OVMF_VARS-*.fd
```

QEMU 固定参数：

```text
-machine q35,accel=kvm
-cpu host
-smp 2
-m 2G
-drive if=pflash,format=raw,readonly=on,file=kvm-config/firmware/OVMF.fd
-display none
-serial tcp:127.0.0.1:端口,server,nowait
```

启动 QEMU 后保存 PID：

```bash
qemu-system-x86_64 ... &
qpid=$!
trap 'kill "$qpid" 2>/dev/null || true; wait "$qpid" 2>/dev/null || true' EXIT
```

不要使用 `pkill -f` 清理 QEMU，它可能匹配并杀掉当前清理命令。只使用保存的 PID。

串口自动化规则：

- 只等待 `IMGLOOP:done`、`automatic login` 和自定义成功标记。
- 不把 shell 输入回显当作命令结果。
- 不连续发送两条命令。每条命令必须先等自己的固定成功标记。
- 不依赖 shell prompt 判断命令已完成。
- 需要执行多步操作时，将完整脚本 base64 编码后作为一条命令发送给 guest。

## 4. 内部 fallback 启动测试

内部场景使用 raw 文件作为唯一虚拟磁盘，不能使用外部 host qcow2：

```bash
qemu-system-x86_64 \
  -name raw-os-internal-test \
  -enable-kvm \
  -machine q35,accel=kvm \
  -cpu host \
  -smp 2 \
  -m 2G \
  -drive if=pflash,format=raw,readonly=on,file="$PWD/kvm-config/firmware/OVMF.fd" \
  -drive if=pflash,format=raw,file="$work/OVMF_VARS-internal.fd" \
  -drive if=virtio,format=raw,cache=none,file="$work/nixos.raw" \
  -display none \
  -serial tcp:127.0.0.1:45581,server,nowait \
  -monitor none
```

必须观察到：

```text
IMGLOOP:start
IMGLOOP:done
```

进入自动登录后，发送下面的一次性内部验收脚本。该脚本同时验证内部 `updateExternalEfi` 和 `nixos-rebuild switch` 使用的 external bootloader install hook：

```bash
internal_script='set -eu
updateExternalEfi >/tmp/internal-update.out 2>&1
grep -q "skip: current UEFI boot uses the internal fallback EFI" /tmp/internal-update.out
/run/current-system/bin/switch-to-configuration switch >/tmp/internal-switch.out 2>&1
grep -q "updated: /boot/EFI/BOOT/BOOTX64.EFI" /tmp/internal-switch.out
test -s /boot/EFI/BOOT/BOOTX64.EFI
echo RAW_INTERNAL_ACCEPTANCE_PASS'
internal_payload=$(printf '%s' "$internal_script" | base64 -w0)
```

通过串口发送：

```text
echo <internal_payload> | base64 -d | sudo bash
```

必须看到：

```text
RAW_INTERNAL_ACCEPTANCE_PASS
```

内部测试成功条件：

- raw 从内部 `EFI/BOOT/BOOTX64.EFI` 启动。
- `IMGLOOP:done` 出现。
- `updateExternalEfi` 返回 0，并输出内部 fallback 跳过信息。
- `switch-to-configuration switch` 输出 `updated: /boot/EFI/BOOT/BOOTX64.EFI`。
- 没有使用或创建 `EFI/Linux/nixos-img.efi`。

如果内部验收标记没有出现，停止测试。不要继续外部启动测试，也不要交付文件。

## 5. 外部自定义 EFI 启动测试

外部场景使用 host qcow2：

```bash
qemu-system-x86_64 \
  -name raw-os-external-test \
  -enable-kvm \
  -machine q35,accel=kvm \
  -cpu host \
  -smp 2 \
  -m 2G \
  -drive if=pflash,format=raw,readonly=on,file="$PWD/kvm-config/firmware/OVMF.fd" \
  -drive if=pflash,format=raw,file="$work/OVMF_VARS-external.fd" \
  -drive if=virtio,format=qcow2,cache=none,file="$work/host.qcow2" \
  -display none \
  -serial tcp:127.0.0.1:45582,server,nowait \
  -monitor none
```

第一次启动必须从外部 ESP 的临时 fallback 文件进入 guest。进入后只执行注册和 `BootNext`，等待 `BootNext` 的实际输出后再重启；不要猜测启动项编号或猜测 NVRAM 是否写入：

```bash
external_boot_script='set -eu
out=/tmp/efibootmgr-create.out
efibootmgr -c -d /dev/vda -p 1 -L NixOS-External -l "\\EFI\\NixOS\\nixos-img.efi" >"$out" 2>&1
boot_id=$(sed -n "s/^Boot\\([0-9A-Fa-f]\\{4\\}\\)\\* NixOS-External.*/\\1/p" "$out" | head -1)
test -n "$boot_id"
efibootmgr -n "$boot_id"
efibootmgr | grep -F "BootNext: $boot_id"
echo RAW_BOOTNEXT_PASS
reboot'
external_boot_payload=$(printf '%s' "$external_boot_script" | base64 -w0)
```

发送：

```text
echo <external_boot_payload> | base64 -d | sudo bash
```

必须先看到：

```text
RAW_BOOTNEXT_PASS
```

随后 guest 重启。确认 guest 已完全关机或完成重启后，离线删除外部 ESP 的临时 fallback 文件：

```bash
sudo qemu-nbd --format=qcow2 --connect=/dev/nbd0 "$work/host.qcow2"
sudo mount /dev/nbd0p1 "$work/mnt/esp"
sudo rm -f "$work/mnt/esp/EFI/BOOT/BOOTX64.EFI"
sudo sync
sudo umount "$work/mnt/esp"
sudo qemu-nbd --disconnect /dev/nbd0
```

再使用同一份 OVMF_VARS 启动。第二次启动只接受以下条件：

- 外部 ESP 只保留自定义 EFI 文件，不再依赖 fallback。
- 出现 `IMGLOOP:done`。
- 出现 `automatic login`。
- `efibootmgr` 显示 `BootCurrent`。
- `BootCurrent` 对应的启动项路径包含 `\EFI\NixOS\nixos-img.efi`。

不要要求固定的 `Boot0005` 编号，编号由全新的 NVRAM 动态分配。启动项路径必须是外部自定义路径，不能用内部 fallback 路径代替。

## 6. 外部 updateExternalEfi 一次性验收

确认第二次启动确实是外部启动后，使用下面的脚本作为一条命令发送。不要拆成“截断—等待—更新—等待—比较”多条串口命令。

```bash
external_update_script='set -eu
info=$(efibootmgr -v)
current=$(printf "%s\\n" "$info" | awk "/^BootCurrent:/ {print \\$2; exit}")
test -n "$current"
entry=$(printf "%s\\n" "$info" | awk -v id="$current" '\''$0 ~ "^Boot" id "[* ]" {print; exit}'\'')
printf "%s\\n" "$entry" | grep -F "\\EFI\\NixOS\\nixos-img.efi"
mkdir -p /mnt/external-esp
mount -t vfat /dev/vda1 /mnt/external-esp
truncate -s 1 /mnt/external-esp/EFI/NixOS/nixos-img.efi
sync
umount /mnt/external-esp
updateExternalEfi >/tmp/external-update.out 2>&1
grep -q "updated: /EFI/NixOS/nixos-img.efi" /tmp/external-update.out
mkdir -p /mnt/external-esp
mount -t vfat /dev/vda1 /mnt/external-esp
cmp -s /boot/EFI/BOOT/BOOTX64.EFI /mnt/external-esp/EFI/NixOS/nixos-img.efi
test "$(stat -c %s /mnt/external-esp/EFI/NixOS/nixos-img.efi)" = 48934400
umount /mnt/external-esp
echo RAW_EXTERNAL_ACCEPTANCE_PASS'
external_update_payload=$(printf '%s' "$external_update_script" | base64 -w0)
```

发送：

```text
echo <external_update_payload> | base64 -d | sudo bash
```

必须看到：

```text
RAW_EXTERNAL_ACCEPTANCE_PASS
```

外部测试成功条件：

- `BootCurrent` 指向外部 ESP 的自定义 EFI 路径。
- 目标 EFI 被故意截断后变为 1 字节。
- `updateExternalEfi` 输出 `updated: /EFI/NixOS/nixos-img.efi`。
- 返回码为 0。
- 目标恢复为 48,934,400 字节。
- `cmp /boot/EFI/BOOT/BOOTX64.EFI` 与外部目标返回 0。

## 7. 成功和失败的判定

只有同时出现下面两个标记才算完整测试成功：

```text
RAW_INTERNAL_ACCEPTANCE_PASS
RAW_EXTERNAL_ACCEPTANCE_PASS
```

以下情况都不能继续，也不能交付：

| 现象 | 判定 | 处理 |
| --- | --- | --- |
| QEMU 进入 UEFI Shell | 启动前置条件失败 | 检查 fallback 文件、BootNext 和 NVRAM；不要向 Shell 发送 Linux 命令 |
| 没有 `IMGLOOP:done` | raw 查找或挂载失败 | 检查 NTFS 中的 `OS-img/nixos.raw`、分区和 hash |
| 内部启动无 GPT UUID | 内部 fallback 的正常情况 | 必须看到内部跳过标记，不是外部测试成功 |
| 外部启动 `BootCurrent` 不是自定义路径 | 未从外部启动 | 恢复外部启动项后重新启动 |
| `Boot entry does not exist` | 使用了猜测的编号 | 从 `efibootmgr -c` 输出动态提取编号 |
| `No space left on device` | ESP 太小 | 重新创建 1 GiB ESP，不复用当前测试盘 |
| 目标仍为 1 字节 | 更新命令没有实际执行或路径不对 | 查看 `/tmp/external-update.out`，不能把 shell 返回码当成功 |
| expect 超时但没有成功标记 | 测试未完成 | 查看串口日志，清理 QEMU 后从当前阶段重新开始 |

## 8. 清理

每次失败或成功后都执行。QEMU 仍在运行时，先使用启动时保存的 `$qpid` 正常结束它：

```bash
set +e
if [ -n "${qpid:-}" ]; then
  kill "$qpid" 2>/dev/null
  wait "$qpid" 2>/dev/null
fi
sudo umount -l "$work"/mnt/esp "$work"/mnt/ntfs "$work"/mnt/raw-esp 2>/dev/null
sudo qemu-nbd --disconnect /dev/nbd0 2>/dev/null
sudo losetup -D 2>/dev/null
set -e
```

不要使用 `pkill -f` 匹配 QEMU。确认没有 QEMU、NBD 或挂载资源残留后，才能开始下一轮。

## 9. 关闭测试配置并交付

两条验收链都出现成功标记后：

1. 删除 `boot.kernelParams = [ "console=ttyS0" ];`。
2. 删除 `systemd.services."serial-getty@ttyS0".enable = true;`。
3. 重新构建最终 system、raw image 和 UKI。
4. 确认最终 raw 内部只有 `EFI/BOOT/BOOTX64.EFI`。
5. 用最终构建产物覆盖 Windows 目录。

```bash
set -euo pipefail

mapfile -t outputs < <(
  nix build --no-link --print-out-paths \
    .#nixosConfigurations.raw_os_core_img_creat.config.system.build.image \
    .#nixosConfigurations.raw_os_core_img_creat.config.system.build.uki \
    --option substituters https://cache.nixos.org
)
image_dir=${outputs[0]}
uki_dir=${outputs[1]}
work=/tmp/raw-os-final-delivery
rm -rf "$work"
mkdir -p "$work"
cp --reflink=auto "$image_dir/nixos.raw" "$work/nixos.raw"
machine/raw_os/docs_script/create-nixos-img-uki-efi.sh \
  "$uki_dir" -o "$work/nixos-img.efi"

sha256sum "$work/nixos.raw" "$work/nixos-img.efi"
stat -c '%n %s bytes' "$work/nixos.raw" "$work/nixos-img.efi"

cp --reflink=auto "$work/nixos.raw" /mnt/n/OS-img/nixos.raw
cp --reflink=auto "$work/nixos-img.efi" /mnt/n/OS-img/nixos-img.efi
sync

sha256sum "$work/nixos.raw" /mnt/n/OS-img/nixos.raw
sha256sum "$work/nixos-img.efi" /mnt/n/OS-img/nixos-img.efi
```

交付文件名固定为：

```text
N:/OS-img/nixos.raw
N:/OS-img/nixos-img.efi
```

未同时通过两个成功标记时，禁止执行交付复制命令。
